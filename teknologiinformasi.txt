 KONSEP & TEORI FUNDAMENTAL
═══════════════════════════════════════════════════════════════

【ARSITEKTUR SISTEM — POLA UTAMA】
• Monolitik: 1 aplikasi besar, deployment tunggal → sederhana tapi rigid
• Microservices: terpecah menjadi layanan kecil, independen → fleksibel tapi kompleks
• Serverless: fungsi sebagai layanan, auto-scale, pay-per-use → hemat operasional
• Event-driven: komunikasi via events (Kafka, RabbitMQ) → decoupling, scalable

【CLOUD COMPUTING — 3 MODEL LAYANAN】
• IaaS: infrastruktur virtual (VM, storage, network)
• PaaS: platform untuk develop & deploy aplikasi
• SaaS: software siap pakai (akses via browser)

RUMUS MIGRASI CLOUD:
Total Cost of Ownership (TCO) = (CAPEX + OPEX) × time

【DEVOPS — 5 CORE PRACTICES】
1. Continuous Integration (CI): kode di-merge dan di-test otomatis
2. Continuous Delivery (CD): deploy ke staging otomatis
3. Infrastructure as Code (IaC): infrastruktur dikelola sebagai kode
4. Monitoring & Observability: sistem terlihat dan terukur
5. Collaboration: dev dan ops satu tim, satu tujuan

【CYBERSECURITY — CIA TRIAD】
• Confidentiality: data hanya diakses yang berhak
• Integrity: data akurat dan tidak diubah
• Availability: data dan sistem tersedia saat dibutuhkan

+ Authentication (identitas), Authorization (hak akses), Non-repudiation (tidak bisa menyangkal)

【DATA — 4 V's OF BIG DATA】
• Volume: jumlah data besar
• Velocity: kecepatan data masuk
• Variety: berbagai jenis data (struktur, semi, non-struktur)
• Veracity: keakuratan dan kepercayaan data

PERTANYAAN: "Bagaimana memilih arsitektur TI untuk startup?"

RESPON:
"Startup butuh cepat dan hemat. 5 pertimbangan:

1. MONOLITIK DULU — UNTUK SPEED:
   - Alasan: early stage, feature masih berubah cepat, tim kecil
   - Kelebihan: deploy cepat, debugging mudah, operasional sederhana
   - Kapan pindah: user 100.000+, tim 15+, team mulai terbagi

2. CLOUD-NATIVE (AWS/GCP/Azure):
   - Kelebihan: scalability pay-as-you-go, managed services
   - Pilih: serverless untuk MVP (Lambda, Cloud Functions)
   - Hindari: over-engineer, pilih yang terbukti dulu

3. DATABASE — PILIH DENGAN BIJAK:
   - Relational (PostgreSQL): untuk data terstruktur, transaksi
   - NoSQL (MongoDB/DynamoDB): untuk data tidak terstruktur, high-scale
   - Jangan premature optimize: mulai dengan yang familiar dulu

4. SECURITY — DASAR DULU:
   - HTTPS, basic auth, rate limiting
   - Encryption at rest (database) dan in transit (TLS)
   - Jangan kompromi: data customer adalah aset

5. MONITORING & OBSERVABILITY:
   - Error tracking: Sentry, DataDog, LogRocket
   - Metrics: Prometheus, CloudWatch
   - Logs: ELK Stack (Elasticsearch, Logstash, Kibana)

RUMUS SEDERHANA:
Startup TI success = Speed × (Right Technology × Right Team)

Tips: pilih teknologi yang tim kamu kuasai. Lebih baik familiar yang work daripada trendy yang bikin struggle.

Roadmap:
- Month 1-3: monolith + single database
- Month 4-6: microservices untuk modul yang sering berubah
- Month 7-9: scale horizontal, caching, CDN
- Month 10-12: observability, security hardening, disaster recovery"
